# Babylon 5 — Endless Sky Part 1

Target: Endless Sky 0.11.2 on Linux.

Part 1 contains B5 ships, equipment, shops, and sandbox testing. Babylon 5 is located at Epsilon. Nothing in the base Endless Sky installation is modified; this is plugin override data.

Artwork is placeholder for testing. Storyline is intentionally deferred to Part 2.

Install by replacing the previous Babylon 5 Part 1 folder in ~/.local/share/endless-sky/plugins/.

### Vanilla alien replacement status

This build intentionally does NOT use an invented `disable government` token. Endless Sky supports plugin overrides of governments, systems, fleets, planets, missions, and events, but governments themselves do not have a documented generic disable switch.

For v0.2.0, vanilla random traffic is removed from Epsilon by replacing that system's fleet list with B5 fleets. A full galaxy-wide vanilla-alien suppression pass should be version-locked to Endless Sky 0.11.2 and enumerate the affected alien systems, fleets, planets, missions, persons, and events so it remains reversible and does not corrupt the base installation.

## v0.2.1 - Jump travel fix

The shared B5 Jump Drive has been made explicit for the Part 1 sandbox:

- `hyperdrive 1` for reliable travel along normal Endless Sky system links.
- `"jump drive" 1` retained for free-jump behavior.
- `"jump range" 250` so B5 ships can reach nearby unlinked systems during testing.
- `"jump fuel" 100` so a Hyperion with 500 fuel has comfortable test endurance.

Because every B5 interstellar ship already installs the common B5 Jump Drive, this fixes travel consistently across all factions without changing individual hulls or the vanilla galaxy map.

## v0.2.2 - Player jump engagement fix

The v0.2.1 drive could select and align to a destination, but a player-controlled
capital ship could remain indefinitely in the ready-to-jump state.

The shared B5 Jump Drive now adds:

- `"jump speed" 10` — permits drive engagement with small residual velocity.
- `"scram drive" 0.5` — permits a small amount of directional drift during
  linked-system travel instead of requiring an essentially perfect stop/alignment.

The existing hyperdrive, jump-drive, 250-unit range, and 100-fuel settings remain.
This is deliberately a sandbox reliability setting; final storyline-era B5 jump
mechanics can be made more restrictive after flight testing is complete.

## v0.3.1 - RPG/Tabletop map rebuild

The earlier v0.3.0 map concept was discarded.

This build is instead based on the Mongoose Publishing Babylon 5 RPG / Galactic Guide
style of galactic geography: a schematic hyperspace jump-route network, with political
territories arranged by transit relationships rather than literal real-space distance.

Key changes:
- Babylon 5 map anchor moved to Epsilon Eridani to match the Mongoose RPG Galactic Guide.
- 41-system first-pass network.
- Earth Alliance, Centauri, Narn, Minbari, League/non-aligned, Vorlon, and Shadow regions.
- Named RPG-era systems include Sol, Proxima, Vega, Jericho, Beta 7, Cyrus, Grissom,
  Quadrant 14, Sigma 957, Raghesh, Quadrant 37, Beta 2/3/4, Minbar, Eshar, Tarellen,
  Tavalan, Valusha, Drazi, Brakiri, Markab, Gaim, Abbai, Yolu, Pak'ma'ra, and Vree.
- The Narn-to-Melat route follows the Galactic Guide's explicit example:
  Narn -> Sorith -> T'il -> Hilak -> Shambah -> Melat.
- Jericho is treated as a major route junction, consistent with the Galactic Guide
  description that it sits at the junction of seven jump routes.
- Epsilon Eridani remains the multi-faction Babylon 5 traffic sandbox.
- Major faction home systems retain their Part 1 shipyard/outfitter test facilities.

This remains a first-pass gameplay implementation. Minor-race governments and exact
restricted/major route mechanics will be layered in after this topology is tested.

## v0.8.2 - Payroll Parser Fix

Endless Sky 0.11.2 does not support an `if` conditional nested inside a mission action.
The previous payroll implementation therefore caused a parser warning when it tried to
interpret `>=` as an assignment operator.

Payroll is now implemented with two parser-valid invisible missions:
- A persistent tracker increments `b5 ea payroll days` with `on daily`.
- An invisible repeating payout mission becomes eligible once the counter reaches 7.
- On the next landing it pays 1,000 credits and subtracts 7 accrued days.
- Any extra accrued days are preserved rather than discarded.

Mission 1 and Mission 2 are unchanged from v0.8.1.

## v0.8.4 - Stellar Systems, Epsilon Planets, and Vorlon Homeworld Security

### Stellar system look and feel
Every system in the Babylon 5 map currently marked as habitable now has a visible

### Restricted worlds
The following planets use a `to land / never` condition and cannot currently be landed on:
- Epsilon III,

- Z'ha'dum.

### Vorlon Homeworld security
The Vorlon Homeworld system now spawns only the dedicated Vorlon homeworld defense fleet.
A pseudo-government named `Vorlon Homeworld Defense` displays in-game as `Vorlon Empire`.
It treats every non-Vorlon government as hostile with a -0.01 default attitude while
remaining friendly toward the real Vorlon Empire government. This makes Vorlon defense
ships attack foreign NPC ships that appear in the system without changing the normal
diplomatic attitudes of the actual Vorlon Empire faction.

The -0.01 hostility is intentionally below Endless Sky's 5% attitude threshold for
propagating player reputation effects between governments.

Missions 1 and 2, commodity trading, weekly Earth Alliance payroll, and the existing
Shadow passive/cloaked behavior are otherwise unchanged.

## v0.8.5 - Permanent Vorlon Homeworld Defense

The Vorlon Homeworld defense force is no longer a periodic system fleet spawn.

attitudes of the real Vorlon Empire government.

All v0.8.4 stellar objects, landing restrictions, commodity trading, missions, payroll,
and Shadow behavior are otherwise unchanged.

## v0.8.6 - Always-On Vorlon Homeworld Defense

The v0.8.5 persistent defense mission had two activation problems:
1. It had no mission location keyword, so Endless Sky treated it as a normal
   spaceport mission rather than activating it automatically.
2. It was gated behind `b5 story start`, so it never existed in the Testbed start.

The defense mission is now independent of the selected start and uses `landing`,
so it activates invisibly as soon as the pilot lands. It also has `to complete / never`,
preventing the foundation mission from completing and removing its NPC fleet.

The Vorlon defense fleet is therefore created once for the pilot and remains stationed
in the Vorlon Homeworld system with `staying`, `hunting`, and `uninterested`.

For an existing save upgraded from v0.8.5, land once anywhere and then depart once so
Endless Sky can activate the invisible mission and spawn its NPC fleet.
